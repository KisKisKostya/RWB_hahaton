# Mesh — интеллектуальная сеть распределения запасов

**Mesh** — хакатонный MVP концепции распределённой логистической сети Wildberries. Система помогает размещать товары ближе к локальному спросу: анализирует продажи по ПВЗ, рассчитывает приоритетный ассортимент, учитывает вместимость точек и планирует перемещения по существующим грузовым маршрутам.

Проект показывает сквозной операционный процесс — от поставки продавца до получения заказа покупателем, включая возвраты, сбои, контроль сроков хранения и финансовые расчёты.

> Это демонстрационный прототип, а не официальный сервис Wildberries и не промышленная интеграция с инфраструктурой маркетплейса. Тарифы, данные и транспортные маршруты в MVP являются демонстрационными.

## Возможности

### Сеть ПВЗ и управление вместимостью
- Просмотр сети ПВЗ и хабов.
- Настройка участия точки в Mesh, площади, высоты и вместимости.
- Учёт как количества единиц товара, так и занятого складского объёма.
- Резервирование ёмкости под операции и освобождение резерва после завершения или отмены заказа.

### Аналитика спроса и ассортимент
- Загрузка недельной истории продаж по ПВЗ.
- Расчёт среднего спроса и целевого запаса.
- Автоматический TOP-5 товаров для каждой точки.
- Учёт габаритов товара, категорийных лимитов и свободного объёма.
- Повторная проверка устаревших TOP-флагов.

### Поставки и перемещения
- Приём поставок от продавцов.
- Подбор точки размещения с учётом спроса и свободной вместимости.
- Перемещение товара между ПВЗ и хабами.
- Разделение партий при частичном перемещении или резервировании.
- Очередь `WAITING_ROUTE`, если подходящего рейса пока нет.

### Маршрутизация
- Редактирование дорожного графа между точками.
- Поиск кратчайшего пути алгоритмом Дейкстры.
- Создание грузовых рейсов с заданной последовательностью остановок.
- Приостановка и повторная активация рейсов.
- Повторный подбор маршрута при сбое.

### Покупательский сценарий
- Демо-профиль покупателя и предпочтительный ПВЗ.
- Поиск доступности товара в ближайших точках.
- Создание заказа и подтверждение получения.

### Возвраты, инциденты и финансы
- Возврат товара в надлежащем состоянии с повторным размещением или отправкой на хаб.
- Возврат повреждённого товара с исключением партии из продажи.
- Регистрация инцидентов при проблемах с маршрутами, вместимостью и состоянием товара.
- Отмена заказа и обработка сбоя доставки с освобождением резервов.
- Контроль истечения срока хранения (TTL).
- Финансовая сводка: продажи, возвраты, комиссия, хранение, логистика, выплаты продавцам и начисления ПВЗ.

## Как работает Mesh

1. **Сбор спроса.** Оператор загружает историю продаж по каждому ПВЗ.
2. **Расчёт ассортимента.** Backend определяет TOP-5 и целевой запас с учётом спроса, габаритов и вместимости.
3. **Приёмка поставки.** Продавец передаёт товар в Mesh, система выбирает допустимую точку размещения.
4. **Перераспределение.** Если товар требуется в другой точке, система ищет подходящий существующий грузовой рейс.
5. **Заказ и выдача.** Покупатель видит доступность товара, оформляет заказ и подтверждает получение.
6. **Обработка исключений.** Оператор управляет возвратами, отменами, сбоями маршрутов и просроченными партиями.
7. **Финансовый результат.** Операции отражаются в начислениях и сводке выплат.

## Быстрый запуск через Docker

### Требования

- Docker Desktop с включённым Docker Compose (Windows/macOS) или Docker Engine и Docker Compose plugin (Linux).
- Git для клонирования репозитория.

### Запуск

Выполняй команды из корневой папки репозитория.

При необходимости создай файл переменных окружения:

**Windows CMD:**
```cmd
copy .env.example .env
```

**PowerShell:**
```powershell
Copy-Item .env.example .env
```

Собери образы и запусти приложение:

```bash
docker compose up --build -d
```

Открой в браузере:

- Frontend: http://localhost:8080
- Swagger / API документация: http://localhost:8080/api/docs
- OpenAPI schema: http://localhost:8080/openapi.json

Nginx раздаёт frontend и проксирует запросы `/api` к FastAPI. Backend не публикуется отдельным портом на хост.

### Полезные команды

```bash
# Состояние контейнеров
docker compose ps

# Логи всех сервисов
docker compose logs -f

# Логи backend
docker compose logs -f backend

# Пересборка после изменений
docker compose up --build -d

# Остановить контейнеры, сохранив данные
docker compose down
```

Чтобы удалить контейнеры вместе с базой данных в Docker volume:

```bash
docker compose down -v
```

> **Внимание:** `docker compose down -v` удаляет volume `mesh_data` со всей SQLite-базой. Не выполняй эту команду, если нужно сохранить данные.

### Хранение данных и переменные окружения

SQLite хранится в именованном Docker volume `mesh_data` по пути `/data/mesh.db` внутри backend-контейнера. Пересоздание контейнера не удаляет этот volume.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | Порт веб-приложения на компьютере |
| `DATABASE_URL` | `sqlite:////data/mesh.db` | Строка подключения к базе |

При первом запуске backend автоматически создаёт таблицы, но не наполняет базу демонстрационными данными. Для создания демо-набора выполни:

```bash
docker compose exec backend python -m app.seed
```

**Важно:** seed-скрипт очищает основные таблицы перед заполнением. Все существующие заказы, поставки, остатки и другие данные будут сброшены. Запускай его только на пустой или не нужной для сохранения базе.

## Локальный запуск на Windows

Открой два отдельных окна терминала. Команды ниже предполагают, что ты находишься в корневой папке репозитория.

### 1. Backend

**PowerShell:**

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

**Если запускаешь впервые и нужна демо-база**, выполни один раз:

```powershell
python -m app.seed
```

Затем запусти API:

```powershell
uvicorn app.main:app --reload
```

Оставь это окно открытым.

> Если PowerShell запрещает активацию виртуального окружения, можно выполнить для текущего окна: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, а затем повторить команду активации.

**Команды для обычного CMD** (если используешь не PowerShell):

```bat
cd backend
python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
```

При первом создании демо-базы:

```bat
python -m app.seed
```

Запуск API:

```bat
uvicorn app.main:app --reload
```

### 2. Frontend

Во втором окне терминала из корня репозитория:

```powershell
cd frontend/pvz
npm ci
npm run dev
```

Открой адрес, который Vite напечатает в терминале. Обычно это:

- Frontend: http://localhost:5173
- Backend API: http://127.0.0.1:8000
- Swagger / документация API: http://127.0.0.1:8000/docs

Frontend обращается к API через относительный путь `/api`. В режиме разработки Vite автоматически проксирует эти запросы на `http://127.0.0.1:8000`.

### Повторный запуск

Когда зависимости уже установлены, повторно создавать виртуальное окружение и выполнять `npm ci` обычно не нужно.

1. Останови старые серверы сочетанием `Ctrl+C` в обоих терминалах.
2. В первом терминале активируй окружение и запусти Backend:

   ```powershell
   cd backend
   .\.venv\Scripts\Activate.ps1
   uvicorn app.main:app --reload
   ```

3. Во втором терминале запусти Frontend:

   ```powershell
   cd frontend/pvz
   npm run dev
   ```

Если открыл новые окна терминала, сначала перейди в корень проекта, а затем в соответствующую папку.

## Данные и демо-наполнение

- Используется локальная SQLite-база: `backend/mesh.db` (при запуске Backend из папки `backend`).
- Таблицы создаются и обновляются при инициализации приложения.
- `python -m app.seed` очищает основные таблицы демо-базы и создаёт набор тестовых данных заново.
- **Не запускай seed при каждом старте**, если хочешь сохранить созданные заказы, поставки, возвраты и изменения.
- Для чистой демонстрации можно предварительно сохранить копию `backend/mesh.db`, а затем запустить seed.

## Сценарий демонстрации

1. Карта сети, параметры ПВЗ и грузовые рейсы.
2. Загрузка недельного спроса и расчёт TOP-5.
3. Поставка от продавца и автоматическое распределение запасов.
4. Поиск товара покупателем, оформление заказа и выдача.
5. Возврат целого и повреждённого товара.

## Ограничения MVP

- Рабочие пространства оператора, продавца и покупателя демонстрационные; промышленной аутентификации и полноценной системы ролей нет.
- Географические данные, дорожные рёбра и остановки грузовых рейсов задаются оператором. Дейкстра работает по введённому графу; live-трафик и внешние API перевозчиков не подключены.
- Фактическое завершение перемещения и передача товара продавцу требуют ручного подтверждения оператора.
- Нет интеграции с GPS транспорта, банковскими платежами, карточными возвратами и реальными выплатами продавцам.
- Тарифы и категорийные ограничения — параметры демонстрационной модели, а не официальные тарифы Wildberries.
- SQLite и локальный запуск подходят для демонстрации MVP, но не рассчитаны на промышленную многопользовательскую нагрузку.

---

**Mesh MVP** демонстрирует подход к распределению товарных запасов по локальному спросу и использованию существующей логистической инфраструктуры для сокращения расстояния между товаром и покупателем.
